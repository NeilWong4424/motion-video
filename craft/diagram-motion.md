# Diagram Motion

## Purpose / Use when

Use for processes, systems, flows, architectures, and relationships whose meaning depends on stable nodes and connectors.

## Reads

Read verified facts, supplied diagrams if any, the Treatment, `data-motion.md` where values are present, and `continuity-first.md`.

## Writes

None. This module performs no artifact writes.

## Must

- Give each diagram node a stable identity and bind each connector to its actual endpoints.
- Reveal a causal or structural relationship only when verified; stage the explanation from context to focal relation to settled conclusion.
- Use shared-element, path, or directional bridging to preserve orientation between Beats.
- Hold the completed relationship long enough to inspect labels and direction.
- Use profile-bound starting ranges only; connector movement follows the message rather than leading it.

## Must not

- Let connectors float independently, imply unverified system behavior, replace the entire diagram at each Beat, or use arrows as decoration.
- Mistake spatial proximity for a verified relationship.

## Stop conditions

Stop when endpoints cannot be bound, labels are ambiguous, the relation is unverified, or motion would make direction/order unreadable.

## Output schema

None.

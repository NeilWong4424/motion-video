# UI Motion

## Purpose / Use when

Use only for supplied and verified UI states, flows, and user actions.

## Reads

Read supplied local UI evidence, verified product facts, the Brief, Treatment, `motion-craft.md`, and `continuity-first.md`.

## Writes

None. This module performs no artifact writes.

## Must

- Tie every depicted action and resulting state to exact supplied evidence and preserve product truth.
- Use a same-node transformation when the UI element remains the same object; preserve stable identity, focus, and hierarchy through the bridge.
- Preroll a real target state if a handoff requires it, then compare before, midpoint, and after evidence for continuity.
- Keep interaction cues legible and allow a settled hold for the outcome.
- Use profile-bound starting ranges only, with behavior subordinate to the verified product action.

## Must not

- Imply a feature, result, or action that is not verified, substitute generated footage, or remount whole UI screens as slides.
- Create a fake target state to smooth a bridge or use UI motion to conceal a product limitation.

## Stop conditions

Stop when UI evidence is missing or stale, an action cannot be verified, an identity claim is false, or no truthful bridge is available.

## Output schema

None.
